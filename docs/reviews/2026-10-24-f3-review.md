public-API edge case (extreme-weight overflow) and several Minor findings.**

(10/10 time-constant blocks, 8/8 aging blocks), the geodesic counter agrees

multigraph cases, the draw contract consumes exactly one uniform per edge,

"unreachable targets count 0" contract and should be fixed (one condition)

aging statistic is correctly labelled exploratory and is not sold as a

## Findings

### Blocker

None.

### Major

**M1 — an unreachable target can report a nonzero geodesic count when a path
sum overflows to `+inf`.**
`CMC.rs/src/percolation/first_passage_shape.rs:677` tests
`dist[u] + weights[edge] == dist[v] && dist[v] > dist[u]`. F1 documents that
a finite sum overflowing `f64::MAX` reads as unreachable
(`first_passage.rs:32-34`), so `dist[v] = inf`; the tight test then sees
`inf == inf` and `inf > dist[u]`, and propagates `ways[u]` into the
unreachable vertex. Repro (legal finite weights):

```
0-1 weight f64::MAX, 1-2 weight f64::MAX, source 0, target 2
dist[2] = inf, reached = 2, geodesic_count = 1, saturated = false
```

This contradicts the module's `geodesic_count_run` contract ("An
unreachable target yields count 0", lines 613–615). No committed gate uses
weights anywhere near `f64::MAX` (Exp/Uniform draws are O(1)), so all
recorded numbers are unaffected. Fix: require `dist[v].is_finite()` (or a
finite candidate sum) in the tight-edge condition; add the two-edge
`f64::MAX` regression and a saturation ladder test.

### Minor

**m1 — `saturated` is run-global, but its doc reads target-local.**
`GeodesicCountOutcome` (`:556-567`) says the count is `u128::MAX` when
`saturated`, and the flag is "whether the exact count overflowed". The DP
sets one flag for any vertex (`:666-693`). A target with exact count 2
reports `saturated=true` when an unrelated branch overflows. Repro: 128
double-edge rungs plus a two-edge branch, target at the branch end →
`count=2, saturated=true`. Rename/document as `any_saturated`, or propagate
a target-specific flag, and add the (currently absent) saturation test.

**m2 — the diagonal `mu <= E tau_e` gate cites the wrong theorem.**
Test lines 361–371 assert `value + t*sem < 1` for every direction with
"subadditivity gives mu <= E tau_e = 1, strictly here (Theorem 2.4)". The
survey's bound and Theorem 2.4 apply to `mu(e1)`; `mu` is homogeneous, and
for `u=(1,1)` the direct-path bound is `2 E tau_e`. Deterministic unit
weights (`E tau_e = 1`) give `mu(1,1) = 2`, and the all-1 profile check
already shows NE = `2n`. The Exp(1) data do satisfy `<1`, but that is an
empirical fact, not Theorem 2.4. Reword: axis directions use Theorem 2.4;
diagonals are reported against 1 as an empirical bracket (or against the
correct `2 E tau_e` bound).

**m3 — "exploratory convergence evidence" overstates the aging ladder.**
Module lines 87–89 call the mean persistence "exploratory convergence
evidence only". The committed sequence is non-monotone (0.6551, 0.7294,
0.6368) and fresh-seed sequences vary (0.738/0.641/0.592;
0.678/0.591/0.685); the gate is a two-radius drift band of ~0.27 on a
[0,1] statistic (`tests/...:563-591`). PERCOLATION is more careful ("no
asymptotic claim (monotone, convergent or otherwise)"). Call it a
finite-size stability check, or report all pairwise drifts and raise R.

**m4 — claimed API semantics are not covered by the six gates.**
The module/Percolation claim parallel edges are distinct geodesics,
`source==target` counts 1, and u128 saturation is explicit, but the
committed tests use only simple grids, never `source==target`, and never a
saturating graph. My independent harness confirms all three (250
multigraphs; self target = 1; 2^127 exact / 2^128 saturated), but a
regression would not be caught. Add the three cases.

**m5 — `geodesic_aging` compares vertex sequences, not edges.**
Signature `:796-812` takes only vertex paths, so on a multigraph two paths
using different parallel edges between the same vertices count as a shared
prefix, contradicting the doc's "leading edges" (`:779-795`). F3 boxes are
simple graphs, so no stage impact. Document the simple-graph/vertex-path
domain, or accept edge sequences from `geodesic_path`.

**m6 — a rejected `realize_with_weights` leaves the weights buffer changed.**
`:383-397` copies caller weights before F1 validation. On a negative/NaN
rejection the profile is intact (tested) but `weights()` now returns the
rejected field, so it is no longer "the weight slice of the last
realization" (`:429-434`). Validate before copying, or document the state.

**m7 — `geodesic_path` doc overstates validation and clearing.**
Doc `:707-719` lists "predecessor indices in range" and "cleared first",
but edge indices cannot be range-checked (no edge count parameter) and
early length/domain failures return before `path.clear()`. Arrays from a
different topology can yield out-of-range edge ids. Adjust the doc or
validate against a supplied edge count.

**m8 — "gated for correctness only" contradicts the aging gate.**
Module `:42-43` says the aging statistic is "gated for correctness only",
but the test also asserts a drift band (`:586-591`). PERCOLATION correctly
describes the band. Fix the module sentence.

**m9 — two wording overclaims in the docs.**
PERCOLATION `:4098` says the anchor lines are "quoted verbatim" in the
module, which is a close paraphrase; and the row/section says "every
consecutive change is negative within 3 combined SEM", while the gate only
rejects an increase larger than 3 SEM (several decreases are 4–6 SEM in
magnitude). The numbers are correct; tighten the wording.

**m10 — `ShapeEstimator` accepts non-finite profiles.**
`add` (`:499-513`) does not reject `inf`/`NaN`; `estimate` (`:517-539`) then
reports `inf` means with `variance = 0`/`SEM = 0` because `.max(0.0)`
swallows NaN. A legal exponential rate near `1e-308` (or a caller profile)
reaches this; the stage's rate 1 does not. Document or reject non-finite
profiles.

### Notes

- **Live-tree clippy is not F3's fault.** The prescribed
  `cargo clippy -p cmc-rs --all-targets --all-features -- -D warnings` on
  the live tree fails with 9 lib + 16 lib-test lints in untracked C/Q files
  (`chayes_machta.rs`, `correlated.rs`, `correlated_thresholds.rs`,
  `sweeny.rs`). On a clean `fc2fdcb` archive the same command **passes**, and
  `cargo fmt --all -- --check` passes. The live tree's tracked `lib.rs`,
  `mod.rs`, and `suite.rs` edits are also outside F3.
- Shape-theorem hypotheses: the module says "for each weight law"; the
  survey's `M` also requires `E min{t_1^d,...,t_{2d}^d} < inf` and
  `F(0) < p_c(d)`. Exp(1) satisfies both; state them for anchor precision.
- Subadditivity gives `lim E[T]/n = inf_n E[T]/n` ("from above"), not
  termwise monotonicity; the non-increase gate is an empirical finite-ladder
  check. The data pass; the text should not call it a theorem.
- `geodesic_count_run` on an empty graph returns `SourceDomain` (there is no
  `EmptyGraph` variant); typed, but worth documenting.
- Duplicate directions/distances are accepted as separate requested pairs
  (6 targets in my duplicate probe); consistent with the "one target per
  requested pair" wording.
- `directions.len() * distances.len()` (`:222-223`) and the `targets` fill
  are unchecked multiplications; only reachable with absurd slices.
- A capacity failure after the F1 pass could leave `ways` partially
  resized; validation rejections (the documented isolation claim) happen
  before F1 and are clean.
- `geodesic_count_run` rejects zero-weight edges even when they can never be
  tight (e.g. a zero self-loop); conservative and documented.
- The per-realization paired norm gap is a statistical estimator, not a
  pathwise triangle inequality (translation invariance does not hold in one
  environment); the CI is the claim, and it is positive.
- The SE gap uses reflection symmetry `mu(1,-1)=mu(1,1)`; worth one sentence
  in the test comment.
