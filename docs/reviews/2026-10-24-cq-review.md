## 3. Independent methods and numbers

### C1 — field and binary gate

Scratch `c1_check` sampled 3000 fields on `[16, 8]`, `[32, 32]`, `[64]`, `[16, 16]`
(a = 1.5 and 0.5) and compared empirical variance/correlation against
`design_correlation`:

```
sides=[16, 8] a=1.5: mean=-0.0124 var=1.0036
   axis0 lag1 0.5871 design 0.5946; lag2 0.3010 design 0.2991
   axis1 lag1 0.5972 design 0.5946
[32,32] a=1.5: var=1.0040; axis0 0.5936/0.3030, axis1 0.5989 (design 0.5946/0.2991)
[64] a=1.5: lag1/2/3 0.5961/0.3012/0.1825 (design 0.5946/0.2991/0.1778)
[16,16] a=0.5: lag1 0.8295/0.8343 (design 0.8405), lag2 0.6627 (design 0.6688)
```

Unit variance and axis isotropy hold; there is no half-mode double counting or axis
swap. The binary gate reproduces 0.0993 / 0.0212 / 0.0049 / -0.0004 / -0.0002
exactly, and these are consistent with the Gaussian-copula prediction
`(1/4)(2/pi) arcsin(rho)`: rho = 0.5946 -> 0.101, rho = 0.118 -> 0.019.

`a=0` is a constant field (bitwise identical values) and `a=inf` delegates bitwise to
`SiteBernoulli`; both tests pass. The `CorrelatedPercolationMC` adapter uses the
unchanged `analyze` + `ObservablePlan`, and the adapter-vs-direct parity test passes.

### C2 — large-L ladder

Corrected invocation (the command in the task places `--release` after `--` and fails
with `error: Unrecognized option: 'release'`; release must come before the `--`):

```
L=128 p_c(L)=0.5139 CI=(0.5039,0.5172)
L=256 p_c(L)=0.5268 CI=(0.5209,0.5296)
L=512 p_c(L)=0.5344 CI=(0.5271,0.5370)
nu=0.934 CI=(0.611,1.257); p_c(inf)=0.5457 CI=(0.5449,0.5464); chi2/dof=0.04
```

The numbers in `PERCOLATION.md` are accurate. The inference is not.

`run_rung` stores `pseudo_critical.standard_error = standard_error(&finite_pc)` where
`standard_error` is `sd / sqrt(n)` (`correlated_thresholds.rs:880, 1022-1032`). The
bootstrap distribution's *standard deviation* is the estimator's bootstrap SE; the
standard error of the bootstrap *mean* is not. At `BOOTSTRAP_RESAMPLES = 200` this is a
factor ~14. The percentile interval (`sorted_pc` 2.5/97.5) is correct, so the struct's
`lower`/`upper` and `standard_error` are mutually inconsistent.

Scratch `bootse` (a=1.5, L=32/64/128, R=128) shows the inconsistency directly:

```
L=32  se_field=0.001629 width=0.069023 implied_sd=0.017608 ratio=0.0925
L=64  se_field=0.000708 width=0.038815 implied_sd=0.009902 ratio=0.0715
L=128 se_field=0.000448 width=0.029468 implied_sd=0.007517 ratio=0.0596
```

(ratios ~1/sqrt(200), slightly above because `finite_pc` drops NaNs).

Recomputing the large-L intercept with `sigma_i = (upper-lower)/3.9199`:

```
intercept = 0.54563, se = 0.00413, 95% CI = (0.53753, 0.55373), chi2/dof ~ 0.000
```

versus the reported `(0.54492, 0.54636)` with `se = 0.00037` (my `c3diag` prints the
per-rung `se` 0.00027/0.00020/0.00024 and widths 0.0133/0.0087/0.0099). The reported CI
is ~11x too narrow. The 0.0027 offset is 0.65 sigma of the corrected statistical error,
not "much smaller than the residual offset". With the corrected sigma the fit residual is
far *below* the bootstrap scatter (chi2/dof ~ 0.000), so `chi2/dof = 0.04` does not
"expose" systematics either; it is an artefact of using the mean's SE as the error. The
same `standard_error` feeds `nu_from_log_derivative`
(`correlated_thresholds.rs:619-628, 648`), so the nu CI is also understated, and
`HarrisBracket::z_score/consistent` and `FlipBracket::separated`
(`weinrib_halperin.rs:197-201, 228-234, 271-281`) inherit it. At a=1.5 the reported
nu = 0.934 +/- 0.165 gives z = -2.4 ("not consistent"); with the bootstrap SD the
measurement is uninformative rather than inconsistent. The boolean is the wrong shape
for this evidence.

Anchor/estimator:

- `percolation_correlated.rs:91`, `PERCOLATION.md:4745-4747`, and the audit line 69 say
  the reference is "1024^2 with 10^4 replicas". Pruessner's text (md lines ~651 and
  ~809) says 10^5 replicas for each size L = 2^l, l = 6..13 (L = 64–8192), and the
  table values are *fit intercepts*, not a 1024^2 run. The module doc
  (`correlated_thresholds.rs:17-21`) has the correct numbers, so the docs contradict
  each other.
- Pruessner defines `p_c^L` from the horizontal wrapping threshold (Eq. 15), not from a
  susceptibility peak. C2's estimator is different, so the residual 0.0027 cannot be
  attributed to "reference scale" without evidence. The module doc itself says the
  primary estimator is the peak of the finite-cluster `chi(p)` (`:45-56`), while the code
  peaks `N Var(S_max/N)` (`:811, 818, 821`). I computed both peaks on the same ladder:

```
L=128 order-param 0.5139 finite-chi 0.5119
L=256 order-param 0.5268 finite-chi 0.5139
L=512 order-param 0.5344 finite-chi 0.5250
```

The finite-chi estimator (the documented one) is ~0.01 lower and would not produce
0.5457. The code choice is defensible, but the method description is wrong.

The ±0.005 tolerance band is honestly described as a band, not CI containment
(`percolation_correlated.rs:125-128`), and the central value 0.5457 passes it. The
problem is the CI/offset narrative wrapped around it.

### Q1 — Sweeny

Exact enumeration (own union-find, `2^12` masks, weight `v^{|A|} q^{k(A)}`) reproduces
the reported marginals. The rate formulas themselves are exact: over all 4096 masks x 12
edges for q = 1, 2, 3 (and q = 0.5), the heat-bath/Metropolis value equals the exact FK
two-state conditional to <= 1.1e-16, both insertion and deletion.

The q=1 bitwise reduction passes. The 12-seed x 2400-proposal fuzz passes against full
recomputation and the forest invariants (tree edges = V - k, parent/child agreement,
partition equality).

The missing gate is real: `git show e2ceb56:CMC.rs/tests/physics/percolation_sweeny.rs`
contains `heat_bath_rate_matches_exact_conditional_on_every_state`; `43e31a8` deletes it
while rewriting the file. `PERCOLATION.md:62, 4800-4803` and audit lines 56/79 still
claim it. I reproduced the property independently, so the *claim* is true; the *gate* is
not in the tree.

**q < 1 bug.** `SweenyRates::new` and the module docs accept any finite q > 0
(`sweeny.rs:19, 213-219`). `propose` assumes the two possible `Delta n` values are
ordered by increasing weight ratio: insertion `(-1, 0)`, deletion `(0, +1)`
(`sweeny.rs:464-466`), so it sets `p_low = accept(delta_n_low)` and
`p_high = accept(delta_n_high)` and uses the unconditional shortcut
`draw < p_low -> accept`, `draw >= p_high -> reject` (`:476-480`). That ordering is
q-dependent:

```
q=0.5: insertion p(-1)=0.571429 p(0)=0.400000 ordered=false
       deletion  p(0)=0.600000 p(+1)=0.428571 ordered=false
q=0.9: insertion 0.425532/0.400000 ordered=false; deletion 0.600000/0.574468 ordered=false
q=1.0: equal (ordered)
q=1.1, 2, 3: ordered
```

For q < 1, `p_low > p_high`, the ambiguous interval is unreachable, and the chain accepts
with the *maximum* of the two rates. Long chains on the 3x3 (400k sweeps, heat-bath)
against exact enumeration:

```
q=0.50: |A|=5.8572 vs exact 6.4144, z=-228.2
q=0.75: |A|=5.2768 vs exact 5.5255, z=-94.4
q=1.00: |A|=4.8017 vs exact 4.8000, z=+0.6
q=2.00: |A|=3.0503 vs exact 3.0511, z=-0.3
Metropolis q=0.5: 6.0000 vs 6.4144, z=-169.7
Metropolis q=2:   3.0446 vs 3.0511, z=-2.6
```

This is a silent distribution error in a documented valid domain. The fuzz includes
q=0.5 but only checks mask/forest consistency, so it cannot see it.

### Q2 — Chayes-Machta

Exact joint check on the 2x2 periodic multigraph (V=4, E=8), q=2 (706 supported joint
states) and q=3 (1458 states). For each active colour I built the exact one-block
transition `P(color) * P(bonds | colour, active)` and applied it to
`mu(A,sigma) ∝ 1{mono} p^{|A|}(1-p)^{E-|A|}`:

```
q=2 active 0/1: max |mu P - mu| = 1.2e-17, total mass 1.000000000000
q=3 active 0/1/2: max |mu P - mu| = 1.1e-17, total mass 1.000000000000
```

So each colour block is exactly stationary; the deterministic colour cycle preserves the
measure. This is stationarity, not detailed balance, and the docs correctly do not claim
detailed balance. The quoted q=2/3 checks reproduce:

```
Q2 q=2: |A| 6.0575 (Q1) vs 5.9830 (CM), diff 0.0745 noise 0.1734; max |A| z 2.96; colour z 1.48
Q2 q=3: |A| 4.5152 vs 4.5145, diff 0.0007 noise 0.1637; max |A| z 3.74; colour z 2.93
Q2 vs R3: CM 6.0958 vs ES 6.0546, diff 0.0412 noise 0.1912
```

The colour z uses a binomial variance `n p (1-p)` with `n = samples * V`, which ignores
intra-cluster correlation; it is a sanity check, not a calibrated test. The |A|
histogram z is the correct marginal binomial per bin. The q=1 bitwise reduction passes.

## 4. Findings

### Blocker

**B1. Sweeny `Delta n` shortcut is inverted for q < 1.**
`CMC.rs/src/percolation/sweeny.rs:464-466, 476-480` (doc contract at `:85-90`).
The public `SweenyRates::new`/`SweenyMC::new` accept any finite q > 0 (`:19, 179-186`);
for q < 1 both insertion and deletion have `p_low > p_high`, so the unconditional
accept/reject interval is invalid and the chain samples the wrong FK distribution.
Reproduction: `/tmp/cqrev2` `cqrev2` binary, q=0.5/0.75 heat-bath and q=0.5 Metropolis
on `build_square(3,3,false)`, 400k sweeps: z = -228/-94/-170 against exact enumeration,
while q=1,2 agree. Fix by ordering the two candidate `Delta n` values by their
acceptance values (or by `sign(ln q)`), or reject `q < 1` with a typed error. The q >= 1
domain used by Q2/Q3 is unaffected and passes all gates.

### Major

**M1. C2 bootstrap SE is the SE of the bootstrap mean, not the bootstrap SE.**
`correlated_thresholds.rs:880` (`standard_error(&finite_pc)`) with
`:1022-1032` (`sd/sqrt(n)`), consumed as the fit weight at `:547-550` and reported at
`:553-558`; the same at `:619-628` (rung slope) and `:648` (nu). Consequence: the
headline `p_c(inf)` CI (0.5449, 0.5464) is ~11x too narrow; the bootstrap-SD version is
(0.5375, 0.5537), and the 0.0027 offset is ~0.65 sigma, not negligible. `chi2/dof=0.04`
is an artefact, not evidence of an excellent fit. `HarrisBracket.consistent` and
`FlipBracket.separated` (`weinrib_halperin.rs:197-201, 228-234, 271-281`) inherit the
error and can flip a verdict. Reproduction: `bootse` ratios 0.06–0.09, `c3diag` per-rung
`se`/width, and the manual weighted fit above.

**M2. C2 anchor and estimator are misdescribed.**
(a) `percolation_correlated.rs:91`, `PERCOLATION.md:60, 4745-4747`, audit line 69 say
Pruessner used a 1024^2 lattice and 10^4 replicas; the anchor says L = 64–8192 and 10^5
replicas (the module doc at `correlated_thresholds.rs:17-21` is correct).
(b) Pruessner's `p_c^L` is the horizontal-wrapping threshold (Eq. 15), not a
susceptibility peak; the 0.0027 residual is therefore not explained by "reference
scale".
(c) The module "Estimator" section (`correlated_thresholds.rs:45-56`) says the peak is
of the finite-cluster `chi(p)`, but the code peaks `N Var(S_max/N)` (`:811, 818, 821`);
on the same ladder the two peaks differ by ~0.01 (0.5119/0.5139/0.5250 vs
0.5139/0.5268/0.5344), so the documented estimator would not yield the quoted number.

**M3. C3 diagnostic numbers for a=1.25/1.0 are not reproducible.**
`PERCOLATION.md:61`, audit lines 72–76. The committed setup/seed gives
`p_c(inf) = 0.5457/0.5374/0.5062` and `nu = 0.934/0.603/1.614` for a=1.5/1.25/1.0, not
`0.5430/0.5317/0.5393` and `0.934/1.020/0.804`; the a=1.5 "0.5430" matches neither the
L=512 peak 0.5344 nor the extrapolation 0.5457, and the a=1.0 ladder is non-monotone
(0.5276/0.5126/0.5126). No test or recorded seed backs the quoted values. The
"unreliable/uncertified" conclusion stands, but the evidence record must be replaced.

**M4. The Q1 rate-level detailed-balance gate documented as passing does not exist.**
`PERCOLATION.md:62, 4800-4803`, audit lines 56/79. Added in `e2ceb56`, deleted in
`43e31a8`; current `percolation_sweeny.rs` ends at the R3 test. I independently verified
the underlying property (max error 1.1e-16 over all masks/edges for q=1,2,3), so the
docs' claim is true about the formulas but false about the gate. Restore the test (and
extend it to q<1 after B1 is fixed, where it will fail until the fix).

### Minor

**m1. Stale/contradictory status text.**
- `PERCOLATION.md:4700-4702` says C2 "does not yet reproduce Pruessner's table" while the
  C2 row says "literature bracket passes"; `:4768` says the binary correlation is not
  gated, but it is (`percolation_correlated.rs:138`).
- `docs/plans/2026-10-23-percolation-roadmap-v2.md:288` still quotes the old 64-replica
  run (`p_c(inf)=0.5383`, CI 0.5246–0.5519); the committed gate uses 256 replicas and
  0.5457.
- Audit line 78's table still says Q2 "detailed balance/R3 comparison open" (R3 is
  closed), and its "time constant" line says 0.580 while the test prints 0.5987.
- `percolation_correlated.rs:50` prints "L=64/128 crossing is absent" for a ladder whose
  sides are 16/32/64.

**m2. Q1 component marginal is printed but not asserted.**
`percolation_sweeny.rs:115-129` computes `component_z` and only asserts `bond_z < 5.0`;
the row's "|A| and k(A) marginals within |z| <= 1.36" is an observation, not a gate.

**m3. Q1 `delta_n_queries` undercounts.**
`SweenyMC::propose` sets `connectivity_queried = true` for the state-update query of an
unconditionally accepted insertion (`sweeny.rs:515, 538`) but does not increment
`delta_n_queries` (only `:482-483` does). The doc says the counter includes insertion
connectivity checks.

**m4. Q2 colour z is not calibrated.**
`percolation_sweeny.rs:245-252` uses `n = samples*V` binomial variance, ignoring
intra-cluster colour correlations, so the reported 1.48/2.93 are not literal z-scores.
Fine as a smoke check; do not describe them as calibrated.

**m5. C1 same-vertex-count geometry is only a caller contract.**
`correlated.rs:710-716` documents that a graph with the same N in a different order is
not detected; the adapter checks only `vertex_count`. A chain of 256 vertices with a
[16,16] law is accepted and silently correlates the wrong sites. Cheap mitigations:
check the lattice is a periodic hypercubic with matching sides (degree/edge count/type)
or require construction from `[L0, L1]`.

**m6. C2 `fractal_dimension` reports a "CI" with `sigma = 1`**
(`correlated_thresholds.rs:661-700`). The interval is a fit-error heuristic, not a
statistical interval; label it as diagnostic.

**m7. C2 finite-cluster susceptibility is reimplemented, not parity-tested.**
`run_rung` computes `(M2 - S_max^2)/(V_active - S_max)` from the incremental summary
(`:781-789`) instead of calling `analyze`; there is no test that the two agree on one
configuration. The primary estimator does not use it, so this is low risk, but the
"reuse" claim should be exact or tested.

**m8. Q3 test comment.**
`percolation_potts_phase.rs:78` says "above it for q > 4"; q=6 is 0.519 (< 5/9) and the
next comment corrects it. Cosmetic, but the test comment is the first thing a reader
sees.
