## Overall verdict

**PASS — no Blocker, no Major. Four Minor findings and several Notes.**
L3 is a genuinely thin layer: it has no second BFS, every realization comes
from `ChemicalDistanceSampler::realize_with_diameter`, the regime semantics
match Biskup exactly (including the `s = 2` no-gate case), the committed run
reproduces every PERCOLATION number, and all four statistical gates survive
fresh-seed re-runs (8/8, 20/20, 20/20, 20/20). L3 may be marked Validated; the
Minors are wording/robustness polish, not corrections to any recorded result.

## Findings

### Minor 1 — `realizations = u64::MAX` panics instead of a typed rejection

`CMC.rs/src/percolation/long_range_diameter.rs:266`:
`Vec::with_capacity(realizations as usize)` is infallible and the only
validation is `realizations >= 2`. Reproduction (scratch probe, clean
commit): `measure_diameter_ladder(&[8], &[1.5], 1.0, u64::MAX, 0)` panics
`capacity overflow` (alloc raw_vec), no ladder, no error. On 32-bit targets
`realizations as usize` also truncates the reservation length. This is
inconsistent with L2's own policy (`long_range_distances.rs:255-290` uses
`try_reserve_exact` and maps failures to `ChemicalDistanceError::Capacity`).
Impact is academic (no realistic caller passes 2^64), but the function is
public and promises typed rejections. Suggested: reject
`realizations > usize::MAX` (or a documented sanity cap) and/or accumulate
via `try_reserve`.

### Minor 2 — the documented seed contract overlaps adjacent rows' RNG streams

`long_range_diameter.rs:267-271` and the module doc `:49-51` (also
PERCOLATION `:4507`): row `r` uses seeds `seed+r .. seed+r+R-1`, so row
`r+1` reuses `R-1` of row `r`'s streams (for the `s=1` gate, 3 of 4; for
`s=1.5`, 11 of 12; the five `s=2.5` rows share 23 of 24). The tests then
feed those row means into OLS and residual CIs as if the size points were
independent. Empirically this does not break anything — the `s=2.5`
cross-base slope sd (0.0117) and A sd (0.0079) are *below* the nominal fit
SEs (0.021, 0.0153), i.e. the committed CIs are conservative, and all gates
pass 8/8 or 20/20. But the contract should say the rows are correlated by
construction; a future revision should use `seed + row*realizations + i` or
hash `(seed, row, i)`. Also note the wrapping addition is not documented
(`seed + r` at `u64::MAX` wraps).

### Minor 3 — "±0.009 / upper CI 0.199" is a residual fit SE, not a seed-calibrated CI

`CMC.rs/PERCOLATION.md:4534-4537` and the row at `:58` present the `s=1.5`
slope as `0.159 +/- 0.009` with "upper CI 0.199". Fresh-seed re-runs give
slopes 0.125–0.214 (sd ≈ 0.022, ~2.4x the nominal SE) and upper bounds
0.151–0.350, because the OLS residual SE ignores seed-to-seed variation and
the row correlation of Minor 2. The *gate* is unaffected: the 0.5 threshold
is cleared by every base even with a seed-calibrated ~95% upper bound (≈0.21).
Relabel the number as a fit SE (as the L2 review asked for the polylog fit)
or report the cross-seed range; do not imply an MC-calibrated interval.

### Minor 4 — "All validation happens before any sampler is built" is not exactly true for `beta`

`CMC.rs/PERCOLATION.md:4514-4515`. `beta` is validated inside
`ChemicalDistanceSampler::new` (`long_range_distances.rs:479-487`), i.e. when
the first row's sampler is constructed, and there is no
`DiameterLadderError::BetaInvalid` — it surfaces as
`DiameterLadderError::Distance(BetaInvalid)`. Reproduction:
`measure_diameter_ladder(&[8], &[1.5], -1.0, 2, 0)` → `Distance(BetaInvalid)`.
No behaviour bug (no draw/row is produced), but the sentence should say
"before any realization is drawn" or add an explicit pre-loop beta check.

### Notes

- `DiameterRegime::Polylogarithmic` could be read as a proved polylog
  *diameter law*; the attached doc is correct (only polylog upper bounds are
  proved, lower bound is log N). Consider naming it for the bound, not the
  law.
- The L3 module doc (`:4-7`) does not repeat L2's caveat that on a
  disconnected realization the "diameter" is the largest within-component
  distance; the PERCOLATION L3 section does, and all gates run at beta=1
  (connected by nearest-neighbour saturation). One sentence in the module
  rustdoc would close the gap.
- The ladder has no guard against `s=2` (the API can measure it); only the
  *gate* is forbidden. This is the right split, but the module could say so
  explicitly next to `supports_diameter_gate`.
- Committed tests do not cover N=1, `[4096]` acceptance, `s=0`, inf/NaN beta,
  or R=0; all behave correctly in this review. Adding N=1 and R=0 is free;
  `[4096]` costs ~0.9 s at R=2 if desired.
- Per-row sampler construction reallocates the O(N²) uniform/CSR buffers for
  every row, even when a size repeats across exponents; documented and
  harmless at these sizes.
- No Carlo.rs adapter / scheduler integration, as documented for L2/L3; no
  new analyzer.
