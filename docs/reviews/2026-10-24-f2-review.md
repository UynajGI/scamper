## 1. The super-source construction (claim 1)

**Derivation.** Give the open box graph G and a set S of source vertices.
Add a vertex σ and edges (σ, u) of weight 0 for every u ∈ S. Any walk from
σ to a box vertex y must begin with exactly one super-source edge (σ has no
other incidences), so the σ→y walks are in weight-preserving bijection with
the union over u ∈ S of the u→y walks: every σ→y walk has weight
0 + w(u→y walk), and conversely. Hence

  dist(σ, y) = min_{u∈S} T(u, y)

exactly, and Dijkstra computes it because all weights are non-negative —
zero weights are legal inputs by the F1 contract (F1's own review verified
zero-weight edges and zero-weight cycles). Dijkstra never needs to "return"
to σ: with non-negative weights the shortest walk is a path, and any
walk revisiting σ is no lighter. This is why ONE pass realizes the min over
the whole source set — no per-source passes, no min-reduction afterwards.

**Structural verification (my code, against the public API).** For every
fresh geometry I decoded the production lattice myself: the box dims
asserted against my independently computed dims (`width·height = n_sites−1`),
every drawn edge a nearest-neighbour box edge under those dims, exactly
`drawn_edge_count()` of them, then `total = drawn + |S|` structural edges
each with weight exactly 0.0, `source = super_source`, and endpoints
decoding to EXACTLY my source set (the full left column for corridors; the
single origin for segments). Targets decode to the right column in row
order / the origin row at `origin + step`. The corridor drawn-edge count
follows `w·r + (w−1)(r+1)` (2×4 → 17, matches) and the segment count
`rows·(W−1) + (rows−1)·W`.

**Draw-free zeros.** `realize` draws exactly `weights[..drawn]` (loop bound
is `drawn_edge_count()`); the structural tail is overwritten with `0.0`
consuming no randomness. Demonstrated empirically in §3 (chained streams)
and §2 (zeros supplied as data in every enumeration assignment).

**Profile semantics.** The profile entry per target is the min over ALL
box paths from ANY source vertex — paths wander across rows freely; there
is no row confinement anywhere in the construction. Proved empirically: my
Floyd-Warshall reference (unconstrained paths, own super vertex) matches
production bit-exactly on every assignment of every fresh geometry,
including width-1 (w < r) and w > r corridors.

## 3. Bitwise draw-contract replay (claim 3)

My RNG driver is written from the published reference algorithm, not the
crate: SplitMix64 seeding (constants 0x9E37…C15 / 0xBF58…5B9 / 0x94D0…1EB),
xoshiro256++ output `rotl(s0+s3, 23)+s0` then the 4-word state update
(`t = s1≪17`, xor chain, `s3 = rotl(s3, 45)`), and the rand-0.10 f64
conversion `u = (x ≫ 11) as f64 · 2^−53` (read from rand's
`distr/float.rs`, re-implemented by me). Cross-validated against
`rand_xoshiro` itself: **10,000 f64 draws across 5 seeds, 0 bit diffs.**

Replay of the documented contract (one f64 per box edge in dense order,
then structural zeros): 4 laws (Exp 1.0, 2.5, 0.3; Uniform) × 4 geometries
(corridor 6×5 E=58+5, corridor 13×7 E=175+7, segment [3,6]m2h2 E=94+1,
segment [1,2,4]m1h1 E=32+1), my seeds: **1,492 weight entries reproduced
bitwise, 0 diffs**; every structural tail entry exactly +0.0. Chained
streams: two consecutive `realize` calls on one seeded stream consume
exactly 2×22 draws — the second realization's weights are draws 23..44 of
my single replay stream, bitwise.

**−0.0 avoidance.** `EdgeWeightLaw::draw(0.0)` returns bits `0` (+0.0) for
rates 1.0, 2.5, 0.3; the naive spelling `−ln(1−0)/rate` returns
`0x8000_0000_0000_0000` (−0.0), which would pass F1's `value < 0.0`
validation yet compare unequal bitwise — the doc's motivation is real and
the `0.0 − ln(1−u)/rate` spelling fixes exactly that. (`u = 0` is
reachable: rand's conversion maps any word with zero top 53 bits to 0.0.)

## 5. The reflection argument (claim 5)

**The argument, in my own words (coupling proof).** Let the box be
reflection-symmetric about its vertical center line (segment([r,2r], r, r)
gives width 4r+1, origin x=r, r-target x=2r ON the axis, 2r-target x=3r;
the reflection R: x ↦ 4r−x swaps origin ↔ 2r-target and fixes the
r-target). R is a graph automorphism of the box, so for any weight field w
the reflected field Rw (weights carried along by R) is well defined, and
path sets map bijectively with identical weights:

  T_w(u, v) = T_{Rw}(Ru, Rv)   pointwise.

Apply with (u,v) = (origin, r-target): T_w(0, re) = T_{Rw}(2r-tgt, r-tgt).
Because the law is i.i.d., Rw =d w, so for any FIXED pair
E T_{Rw}(a,b) = E T_w(a,b); hence

  E T(0, re) = E T(r-target, 2r-target)   — exact.

Concatenation: T_w(0, 2re) ≤ T_w(0, re) + T_w(re, 2re) pointwise (join the
two optimal box paths; a walk's weight upper-bounds the infimum, and with
non-negative weights the walk infimum equals the path infimum). Take
expectations and insert the identity: E T(0, 2re) ≤ 2 E T(0, re) — exact on
the finite symmetric box, no boundary correction. **The argument is
correct.** (The same reflection shows why the corridor does NOT enjoy it:
the min over the left column is not mapped to a single-point start by any
box symmetry.)

**Empirical verification** (segment([8,16],8,8), my fields, N = 40,000):

- Pointwise coupling T_{Rw}(r, 2r) = T_w(0, r): **0 violations**, max
  relative difference 6.3e−16 (pure float addition-order noise).
- Invariance check T_w(0,2r) = T_{Rw}(0,2r) (R preserves the
  {origin, 2r-target} set): max relative difference 8.3e−16 across 40,000
  reflected-field pairs (13,584 bitwise identical).
- Concatenation T(0,2r) ≤ T(0,r) + T(r,2r): **0 violations**.
- The expectation identity: mean T(0,r) − mean T(r,2r) = −0.00128 ±
  0.00727 (z = −0.18). Honest log: at N = 400 and N = 4000 the same
  statistic sat at −2.4σ with my earlier seeds; the N = 40,000 run closes
  it, and the pointwise coupling above rules out any systematic asymmetry
  — the smaller-sample gaps were fluctuations, and I confirmed the
  production engine itself is not the source (the coupling identity is
  machine-verified per field).

## 6. Statistical machinery (claim 6)

- **SEM math.** `variance = (Σx² − (Σx)²/n)/(n−1)` (unbiased), clamped at
  0; `standard_error = sqrt(variance/n)`. On 900 synthetic profiles with
  known statistics the production estimator matches my two-pass
  computation to <1e−9 relative (mean, variance, per-target mean/variance,
  per-target SEM). Correct.
- **CI construction.** The chi gate's CI is a naive OLS t-CI on the slope
  of (ln r, ln Var_hat): residual-based slope SE with df = 3 and
  t_{0.975,3} = 3.1824 (correct critical value). It is NOT a bootstrap or
  formal delta-method; it is adequate here because (i) the points are
  independent across r, (ii) the dominant scatter IS the sampling error of
  ln Var_hat (delta-method SE ≈ sqrt(2/(N−1)) ≈ 0.058 at N = 600, matching
  the residuals), (iii) the ln-transform's Jensen bias ≈ −1/(N−1) ≈ −0.0017
  is common to all points and cancels in the slope, and (iv) the gate
  makes no claim the CI can't support (bracket inside (0,1/2) only; my
  independent CI is narrower and agrees). See Note N1.
- **SEM ~ 1/√N.** My nested-prefix subsampling of ONE 3,200-realization
  chain (corridor 32×16, Exp(1), my fields): SEM 0.127053 (N=100) →
  0.087086 → 0.061940 → 0.043596 → 0.031853 → 0.021940 (N=3200);
  log-log slope **−0.5008 ± 0.0058** (R² = 0.9995); ratio 3200/100 =
  0.1727 vs 1/√32 = 0.1768. The committed gate's ratio (0.531 at
  512/128) reproduces bitwise on re-run.

### Notes

- **N1 — chi CI is a naive OLS t-CI** (df = 3), not bootstrap/delta-method.
  Adequate for the bracket-only claims made (see §6 for why the
  approximation is benign at N = 600); if F3 ever tightens the bracket
  toward 1/3 it should upgrade to a paired/heteroscedastic or bootstrap CI.
- **N2 — subadditivity/time-constant gates use UNPAIRED difference SEMs on
  PAIRED data** (T_r and T_{2r} measured on the same realizations).
  Empirical correlation is small (corr = +0.04 at r=8), so little power is
  lost; my paired variant confirms the direction at 17–22σ. If the gate is
  ever expected to catch near-violations, pair the differences.
- **N3 — `weights()` rustdoc wording.** "The weight slice of the last
  realization": after a REJECTED `realize_with_weights` (bad VALUES — the
  copy precedes F1 validation), the slice holds the rejected field while
  the profile correctly stays intact (the committed test pins the profile
  half). A one-word clarification ("last accepted run, or the field of a
  rejected run") would close it.
- **N4 — roadmap letter vs delivered geometry.** Roadmap §3 F2 says "all
  edge-weight assignments on a 4×4 corridor"; with r = w = 4 that is E = 36
  (2^36, infeasible). The stage delivered E ≤ 17 corridors (and says so);
  my fresh enumeration covers the literal 4×4 BOX corridor (r=3, w=4,
  E = 24, 2^24 = 16,777,216 assignments, 0 mismatches), closing the gap
  between the roadmap's letter and the delivered set.
- **N5 — throughput numbers are honest but wobble** run-to-run (doc 233/55
  debug; my rerun 220/52; release 1,617/384). The doc labels them
  "eprintln-timed, debug profile" — fine, just don't treat them as
  contracts.
- **N6 — one-pass sum/sum_sq accumulation** in `PassageEstimator` is
  cancellation-prone in principle; at this layer's magnitudes (|T| ≲ 10³,
  N ≲ 10⁵) the error is far below the reported precision (verified <1e−9
  against two-pass). Welford would future-proof F3's larger ladders.
