## 1. The law, from scratch (claim 1)

**Re-derivation.** From the module rustdoc: dense vertex indices are
row-major lexicographic ranks; the consideration order is lexicographic
(x, y) with x < y, equivalently ascending pair index
`x·n − x(x+1)/2 + (y − x − 1)`. Re-derived the formula myself:
pairs with first endpoint below x contribute Σ_{a<x}(n−1−a) =
x(n−1) − x(x−1)/2, and (x, y) is offset (y−x−1) inside x's block; total
xn − (x²+3x)/2 + y − 1, algebraically identical to the doc formula. The law
itself is the explicit power-law member of Biskup's family
(archive line 84: `p_xy = 1 − exp{−|x−y|^{−s+o(1)}}`, line 214 Eq. (1.7)
`1 − exp{−β(1+|x−y|)^{−s}}`): stage L1 realizes `p(r) = min(1, β r^{−s})`,
first-order equivalent to Eq. (1.7) at small βr^{−s} — exactly what the
docs claim, and the regime statements are explicitly deferred to L2/L3.

**My own sampler.** I wrote an independent SplitMix64-based RNG (53-bit
uniforms), an independent odometer-based coordinate/pair enumeration, and my
own probability expression `min(1, beta / r^s)` (deliberately a different
but mathematically equal formula than the pinned
`(beta * r^(-s)).min(1.0)`).

- **Bit-exact replay (matching RNG):** with identically seeded
  `Xoshiro256PlusPlus`, the adapter's `realize`, a manual one-f64-per-pair
  draw through the RNG-free `long_range_run`, and my own threshold
  decisions from my own enumeration all agree bit-for-bit on the occupied
  set: 24/24 cases across boxes [8], [4,4], [13] × 8 seeds.
- **Statistical replay (my RNG):** for 5 (box, β, s) configs and R =
  20,000 realizations each (100,000 total), production's occupied set
  equaled my replay decisions on **every** realization (replay-mismatch =
  0); per-pair frequencies vs my law: max |z| = 2.49 / 1.80 / 2.33 / 2.26 /
  2.50; pooled chi-square (1 df per unsaturated pair) 33.0/22.2/21.0/102.9/
  87.7 at df 28/28/21/120/83, standardized (chi2−df)/√(2df) = 0.67 / −0.77
  / 0.00 / −1.10 / 0.36 — all healthy. Saturated pairs (7 on [8] at
  β=2.5, 22 on [3,5] at β=1.4) always occupied, as the law demands.
- **Bit-adjacent threshold replay:** for every pair of the 5 configs (309
  pair-law combinations: [8] at three laws = 84, [4,4] = 120, [3,5] = 105),
  u = next-below(p) occupies exactly that pair and nothing else; u
  = 1.0 never occupies (strict `<`, also at p = 1); u = next-above(p) never
  occupies — 0 failures.
- **Expression pinning quantified:** my `beta/r^s` vs the pinned
  `beta*r^-s` differ bitwise on 159,763 of 540,672 grid points
  (r = 1..4096 × 11 β × 12 s), always ≤ 2 ulps. This is why the docs pin
  THE expression and say replays must mirror its bits — honest and correct;
  the ulp-level difference is statistically unobservable (probability of a
  uniform landing between them over my 100k realizations ≈ 10⁻¹⁰, and 0
  occurred).

**Methodology disclosure.** My first sampler design seeded per-realization
RNGs with consecutive integers, putting all streams on the same γ-lattice
with offset rep+k — every pair effectively reused the same 20,000 uniforms
and the pooled chi2 collapsed to a single empirical-CDF statistic
(chi2 = 28 at df = 120, z_chi = −5.9). I diagnosed this in my own RNG
(window-sum experiments) and fixed it by scrambling stream starts; the
numbers above are from the fixed design. Production was never implicated:
the committed tests seed via `Xoshiro256PlusPlus::seed_from_u64`, whose
rand_core default hashes the u64 seed into the full 32-byte state —
properly decorrelated, as their healthy chi2/df ratios (1.19/1.29/1.10/0.92
at R = 600) show.

## 2. Pair indexing (claim 2) — one Major finding

Verified with my own enumeration (coordinate odometer; ranks computed by my
own mixed-radix arithmetic — which also confirms "dense order is coordinate
lexicographic order" exhaustively):

- `pair_endpoints(k)` equals my k-th lexicographic pair on [5], [3,4],
  [2,2,3], [4,4], [1], [1,1,1] — every pair, endpoints x < y;
  `pair_endpoints(pairs)` is None.
- `pair_index` inverts it on every pair and is symmetric in its arguments;
  `pair_index(x, x)` is None. The doc formula matches my enumeration.
- 1,600 random inverse samples on [7,5,6], [10], [17,3], [1,9,2,4] plus
  distance fuzzing against my coordinate ℓ1 — all pass, both argument
  orders.
- The binary search in `pair_endpoints` (largest a with
  `base(a) = a·n − a(a+1)/2 ≤ pair`) was checked by hand on small cases and
  exhaustively above; `base` is strictly increasing on 0..V−1, `base(V−1)`
  = pairs > pair for every valid pair, so the search is well-founded.

**Major M1 — `LongRangeBox::coordinates` returns the axis-reversed vector
for d ≥ 2.** The slot loop iterates `coords.iter_mut()` (axis 0 first) but
zips it with `self.sides.iter().rev()` (last side first), writing the digit
of axis d−1−j into slot j. Consequences, from my minimal reproduction
(`round trip: coordinates(i) then vertex_index`):

```text
sides=[3, 4]: coordinates(1) = [1, 0]  (correct: [0, 1]; vertex_index([1,0]) = 4)
sides=[3, 4]: coordinates(3) = [3, 0]  (not even in the box; vertex_index -> None)
sides=[4, 4]: 12/16 round-trip failures; sides=[2,2,3]: 8/12; sides=[8]: 0/8
```

`coordinates` is a public accessor documented as the "row-major
decomposition" (the natural inverse of `vertex_index`, which my checks
confirm is itself correct). Nothing in the repo calls it (grep: the only
`coordinates` hits are other types), the realization path never touches it
(distance decomposes digits inline, correctly), and no L1 gate exercises
it — which is why 8/8 committed tests pass. But it is a silent-wrong-answer
trap for exactly the consumers the docs anticipate (L2 distance profiles /
L3 diameters in d ≥ 2). Fix: iterate the slot loop in reverse too (or drop
both `.rev()`s), and add `coordinates ∘ vertex_index = id` to the gate that
already pins `pair_index ∘ pair_endpoints = id`. Classification: Major
follow-up, not a Blocker — no stage claim depends on it.

## 4. Independence (claim 4)

21 fresh pair-pairs (none overlaps the committed probes), R = 20,000, my
RNG, joint occupancy of the two pairs vs the exact product q = p₁p₂,
z = (rate − q)/√(q(1−q)/R):

- 1×16, (β,s) = (0.5, 1.0), 8 probes incl. a shared-vertex pair (3,7)&(7,12):
  \|z\| ≤ 1.02 (e.g. (5,11)&(2,13): rate 0.00390 vs q 0.00379, z = 0.26).

  (r ≤ 2 shells) jointly occupied in 20,000/20,000 realizations;
  saturated+probabilistic probes z = −2.45 / 0.33 / −2.12 (e.g. pair (0,1)
  with p=1 and pair (9,13) with p=0.5: rate 0.49135 vs q 0.5 — the joint

- 1×16, (0.4, 3.0) — near-zero extreme: p(15) = 1.185e−4; three probes
  with q·R ≤ 0.026 observed 0 joint occupancies (Poisson-bounded, pass);

  \|z\| ≤ 0.71).
- 5×5, (0.7, 1.5), 4 probes: \|z\| ≤ 0.34.

21 ≥ 20 required. No evidence of dependence anywhere.

## 6. G1 driving semantics + G3 padding precedent (claim 6)

- All-vertices-at-step-0 verified in §5 (the n leading trajectory entries
  carry step coordinate 0 and the isolate summaries; the module doc's "G2
  convention" framing is accurate).
- Added-edge-count coordinate: trajectory steps are exactly
  `[0; n] ++ [1..=m]` — verified as vector equality on every seed of §5.
- Padding: `history[i] = summaries[n+i].largest_component_size` for
  i < min(steps, m) and the final largest size otherwise, verified
  **bitwise** (f64 bits) for steps_len ∈ {1, 5, 40, 300} × 10 seeds on
  [13] (m ∈ [28, 35]: steps_len 1 and 5 exercise truncation, 40/300 the
  tail), plus beta = 0 (m = 0) where the tail is all 1.0.
- G3 precedent (`invasion.rs` realize): same convention — fixed length
  `steps`, entry i = i-th accepted event value, tail repeats the final
  value, vacuous case 0.0. L1 differs only in the vacuous base: with no
  added edges the "final value" is well-defined (largest component = 1,
  all vertices active), so L1 repeats 1.0 rather than a sentinel. Same
  semantics, honestly documented in both places ("entries past the
  realized length repeat the final value (1 when nothing was added)").

## 7. Zero materialization (claim 7)

- Implementation: `PairUniverse<'a>` holds exactly one `&LongRangeBox`;
  no Vec/HashMap anywhere; `edge_endpoints` decomposes via binary search;
  `incidences` filters 0..V through O(1) `pair_index`. The union-find
  substrate never asks for a materialized edge list — confirmed by reading
  `activate_vertex`/`activate_edge` (they read `edge_state[edge]` and call
  `graph.edge_endpoints(edge)` only).
- Probe re-run (see §8 log): `LONG_RANGE_PROCESS_ALLOC` reports
  allocations_per_realization = 0.000 and bytes = 0.000 at 1×256 (32,640
  pairs), 1×512 (130,816 pairs), 16×16 (32,640 pairs), 128 measured
  realizations each, with the hard `assert_eq!(count_total, 0)` — passes.
- **Minor M2:** the `PairUniverse` doc comment says "every edge endpoint
  lookup is O(1)". `pair_endpoints` is a binary search over
  0..vertices — O(log V), correct but not O(1). (The review scope's own
  phrasing presumed O(1); the code comment overstates.) The O(V²) vertex
  stage cost IS honestly disclosed in the Limitations section.

## Findings

**Blocker — none.**

**Major**

- **M1** `LongRangeBox::coordinates` (`CMC.rs/src/percolation/long_range.rs`
  ~184–195): axis-reversed output for d ≥ 2 (slot loop forward, sides loop
  reversed). Returns vectors that are not even in the box
  (e.g. `coordinates(3) = [3,0]` on [3,4]). Public API, documented as the
  row-major decomposition; currently zero in-repo callers and off the
  realization path, so no L1 claim or gate is affected — but a silent trap
  for L2/L3 consumers. Fix + add the `coordinates ∘ vertex_index = id`
  gate.

**Minor**

- **M2** `PairUniverse` doc comment ("every edge endpoint lookup is O(1)"):
  it is a correct O(log V) binary search. Doc-only fix.

**Notes**

- **N1** The committed degree gate tests the center vertex only; corners
  (and 2D center/edge/corner) pass with the same machinery — the boundary
  framing is empirically sound (my §3 table). Worth folding one corner
  case into the committed gate when M1 is fixed.
- **N2** `pair_probability(r, β, s)` accepts r = 0 (yields 1 for s > 0 via
  0^{−s} = ∞ → min) — out of the documented r ≥ 1 domain, unreachable
  through the pair universe (distinct vertices); a doc sentence would do.
- **N3** Two equal expressions of the law (`beta/r^s` vs pinned
  `beta*r^{−s}`) differ on ~30% of (r, β, s) grid points at ≤ 2 ulps —
  the pinned-expression contract is the right call and is documented as
  such; nothing observable follows statistically (0 straddles in 100k
  realizations).
- **N4** `LongRangeError` is not `#[non_exhaustive]` — consistent with the
  sibling process error enums; future variant additions are breaking, as
  elsewhere in this crate.
- **N5** My verifier's first statistical design was flawed (shared-uniform
  streams across pairs); fixed before any conclusion was drawn and
  disclosed in §1. Production seeding (`seed_from_u64` into the full
  xoshiro state) is properly decorrelated.
